# Troubleshooting

## 1. `attack` / `smoking` 클래스 혼동

### 문제

`attack`과 `smoking`은 팔과 손이 상체 주변에 위치하는 경우가 많아 일부 프레임에서 혼동이 발생했습니다.

### 접근

- 혼동 이미지와 라벨을 다시 확인했습니다.
- 클래스별 라벨 기준을 정리했습니다.
- 손 위치, 팔 자세, 객체 박스 형태가 애매한 데이터를 정제했습니다.
- 정제된 데이터로 재학습해 클래스별 성능을 다시 확인했습니다.

### 배운 점

> 비슷한 자세 기반 클래스는 모델 구조보다 데이터 기준과 라벨 일관성이 성능에 크게 영향을 준다는 점을 확인했습니다.

---

## 2. Hailo 변환 후 미탐지 또는 입력 크기 문제

### 문제

학습 환경에서 정상 동작하던 모델이 Hailo 배포 환경에서 입력 크기나 전처리 차이로 미탐지되는 문제가 발생할 수 있었습니다.

### 접근

- 학습 시 사용한 입력 크기와 변환 후 입력 크기를 비교했습니다.
- 모델 전처리 방식과 추론 파이프라인의 입력 형식을 점검했습니다.
- 배포 환경에서 동일한 테스트 이미지를 사용해 출력 차이를 확인하는 방식으로 원인을 좁혔습니다.

### 배운 점

> 엣지 가속기 배포에서는 모델 성능뿐 아니라 입력 크기, 전처리, 출력 후처리의 일치 여부가 중요합니다.

---

## 3. YOLO + MediaPipe 동시 사용 시 FPS 저하

### 문제

YOLO 탐지와 MediaPipe Pose 분석을 동시에 수행하면 CPU 사용량이 증가하고 FPS가 저하될 수 있었습니다.

### 접근

- 모든 프레임에서 Pose를 실행하지 않고 필요한 상황에 집중하는 구조를 검토했습니다.
- Hailo 가속으로 YOLO 추론 부하를 줄이는 방향을 적용했습니다.
- FPS와 latency를 함께 확인해 실시간 처리 가능 수준을 검증했습니다.

### 배운 점

> 실시간 로봇 시스템에서는 정확도뿐 아니라 지연시간과 FPS를 함께 고려해야 하며, 모델 실행 조건을 설계하는 것이 중요합니다.
